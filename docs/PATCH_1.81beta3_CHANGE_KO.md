# Dugout Atlas 1.81 beta3 — Change 분석 패치

## 이번 변경

Profile·Matchup의 계산을 유지하고 Change 탭에 구속·회전수 전후 비교를 추가했다. 패치 이름은 1.81 beta3이고 정식 앱 버전(config/settings.py·pyproject.toml)은 1.8을 유지한다. main 커밋/push는 하지 않았다.

## 사용법과 수동 확인

1. 선수 페이지에서 투수를 선택하고 **투수 분석 → Change**를 연다.
2. 시즌·기준일·일별/주별을 고른다. 새 선수 응답이 도착하면 선수 페이지의 시즌으로 맞춘다. Change 안의 시즌은 독립적으로 변경할 수 있다.
3. 조회 범위·TTL 안내를 읽고 **Change 분석하기**를 누른다. 기본은 현재 메모리 캐시만 사용한다.
4. 원시 캐시가 없으면 조회 없이 안내한다. 필요한 경우 **원시 캐시가 없으면 선택 시즌 1회 조회 허용**을 체크한 뒤 다시 누른다. 이 선택은 설정 파일에 영구 저장하지 않으며 선수 전환 시 해제된다.
5. 조회 후 구종을 선택한다. 구종 변경은 집계 결과를 골라 표시하므로 추가 요청이 없다.
6. 이전/이후 카드, 중앙값·IQR 차이, 날짜별 유효 N·결측·제외 표를 확인한다. 날짜나 시즌·간격을 바꾸면 결과를 비우므로 다시 분석한다.
7. 기준일 당일은 이후에 들어가는지, 한쪽 표본이 없을 때 차이가 ‘—’인지, 캐시 없는 오프라인 상태에서 자동 요청하지 않는지 확인한다.
8. Windows 11에서 EN/KO/JA, 밝게/어둡게/강조색, 작은 창·글자 확대를 확인한다. 기존 타자 화면·Pitch Arsenal·Profile·Matchup·구속 이력도 확인한다.

## 데이터 계약과 계산

- 선수 식별: `pitcher`가 모든 행에서 선택 MLBAM ID와 일치해야 한다. 혼합·확인 불가 ID는 실패로 처리한다.
- 행 선택: 유효한 `game_date`의 연도가 선택 시즌이고 `game_type == R`인 정규시즌만 포함한다. 잘못된 날짜·다른 연도·다른 경기 유형은 제외 행 수에 포함한다.
- 구종: `pitch_type`으로 묶고 빈 구종은 미분류 수로 따로 표시한다. 서로 다른 구종을 합치지 않는다.
- 이전: `game_date < 기준일`. 이후: `game_date >= 기준일`.
- `release_speed`: mph. `release_spin_rate`: rpm. 방향·좌우투 반전은 적용하지 않는다.
- 각 구간/구종/지표의 중앙값과 IQR(Q3−Q1), 유효 N을 계산한다. 차이는 이후−이전이다. 양쪽 유효값이 있어야 차이를 계산하며 없으면 None/‘—’다.
- 결측: null 또는 빈 문자열. 제외: 결측이 아니지만 비숫자·무한대·0 이하인 구속/spin. 각 지표에서 **유효 N + 결측 + 제외 = 구간 투구 수**다. 원시 컬럼 자체가 없으면 unavailable이며 전부 결측으로 계수한다.
- 유효 N<30이면 해석 주의를 표시한다. 30은 화면 안내 기준으로, 통계적 유의성이나 신뢰도를 보장하는 기준이 아니다.
- 일별은 경기 날짜, 주별은 월~일의 원시 투구를 모아 중앙값을 계산한다. 일별 중앙값의 평균이 아니다. 주별 표시는 해당 주 월요일이다. 기준일을 걸치는 주도 있으므로 전후 카드는 일자 기준으로 별도 분할한다.
- 기록 없는 날짜/주는 만들지 않는다. 기록은 있으나 지표가 모두 결측인 날짜는 중앙값 없음으로 표시하고 그래프 선을 끊는다. 그래프 점의 N과 상세 표를 함께 제공한다.
- 전체 raw 행 수, 정규시즌 행 수, 구종 분류/미분류, 범위·경기 유형 제외 수를 표시한다. 지표별 제외와 행 제외는 서로 다른 집계다.
- UI/PlayerBundle에 raw DataFrame은 전달하지 않는다. worker에서 계산한 숫자·문자열·목록·dict만 전달한다.

## 실제 필드 검증과 IVB/HB 제한

기존 실응답 fixture `tests/fixtures/pitch_analysis/savant_669373_2025-09-06.csv`를 다시 읽어 검증했다. MLBAM 669373의 2025-09-06 정규시즌 90구이며 최초 출처/조회 조건은 `PATCH_1.81beta_KO.md`에 기록되어 있다.

|필드|확인된 비결측|값 범위/구분|
|---|---:|---|
|pitcher|90/90|669373|
|game_date|90/90|2025-09-06|
|game_type|90/90|R|
|pitch_type|90/90|실응답 구종 코드|
|release_speed|90/90|86.2–98.7 mph|
|release_spin_rate|90/90|1648–2499 rpm|

이 fixture는 원래 응답의 일부 컬럼만 보존한 파일이다. IVB/HB 필드가 fixture에 없다는 사실이 Savant 전체에 해당 필드가 없다는 뜻은 아니다. 원본 전체 응답의 IVB/HB 필드·결측률·단위·방향은 이번 작업에서 **미검증**이다. IVB/HB는 사용 불가로 명시하고 계산·변환·그래프를 제외했다. total vertical movement를 IVB로 바꾸거나 추정치를 넣지 않는다. 향후 공식 정의와 실제 원본 필드·단위·부호를 함께 확인해야 추가할 수 있다.

실제 날짜 변화까지 실데이터로 검증했다고 주장하지 않는다. 다일 경계·주별 계산 테스트와 화면 예시는 synthetic 자료임을 명시했다. 이번 작업에서 새 실제 네트워크 요청은 하지 않았다.

## 조회량과 캐시

- 기존 `StatcastService.season_dates()` 범위 그대로 사용: 3월 1일~11월 30일, 당해 시즌은 오늘까지. 분석은 반환된 정규시즌 행만 사용한다. 시즌 종료일을 추측하지 않으며 관측 최소/최대 날짜도 별도로 표시한다.
- 유효 메모리 raw가 있으면 새 요청 0회. 없으면 기본 동작은 cache_miss 반환으로 끝난다.
- 사용자가 체크한 경우에만 기존 `pybaseball.statcast_pitcher` 시즌 호출 1회를 허용한다. 현재 설치된 pybaseball `split_request` 소스는 최대 2190일 단위로 나눠 한 시즌은 예상 HTTP 1회다. 라이브러리 버전·외부 서비스에 따른 내부 요청 수/대기 시간은 보장하지 않는다. 무제한 과거 재수집, 자동 재시도 루프, 다른 시즌 탐색은 추가하지 않았다.
- 같은 투수·시즌·조회 기간의 메모리 raw를 기존 Arsenal·velocity history·Profile·Matchup과 공유한다. 기존 lock으로 동시 호출을 합친다.
- 기존 TTL 유지: 현재 설정상 당해 시즌 15분, 과거 시즌 30일. 메모리 항목 최대 2개. TTL 이내라도 종료/퇴출되면 raw는 사라진다. 앱 관리 raw 영구 캐시는 추가하지 않았다. pybaseball 외부 캐시 설정도 바꾸지 않는다.
- SQLite·캐시 스키마/DB migration/데이터 자동이관 없음. 사용자 DB·설정·캐시를 삭제하거나 초기화하지 않는다.

## 미구현과 다음 단계

IVB/HB 분석, 기준일 전후 같은 길이 사용자 기간, raw 디스크 영구 캐시, 새 조회 진행률/네트워크 취소, 변화 원인·피로·부상·최적 폼 판단은 포함하지 않는다. 현재 pybaseball 전송의 긴 대기 가능성은 기존과 같고 worker로 UI를 보호한다. 실제 Windows 실행과 실제 다일 응답의 관측 범위/결측 확인이 다음 수동 검토 단계다.
