# Dugout Atlas 1.81beta — 투수 분포·상황별 분석 패치

기준 소스: main `d40126c7371ce83742b0aafe674a1426b0b4a7b4` (앱 v1.8).
이번 전달 파일의 이름은 1.81beta이며 정식 앱 버전·pyproject 버전은 1.8을 유지한다. main 커밋/push는 하지 않았다.

## 사용법

선수 페이지에서 투수를 선택한다. 기존 Arsenal과 차트 아래 **투수 분석 · 1.81beta**의 **투수 분석 불러오기**를 누른다.

- Profile: 구종별 구속(mph) 또는 회전수(rpm)의 중앙값, IQR, 표본 표준편차, P10/P90와 분포를 표시한다. 상자는 Q1~Q3, 수염은 P10~P90이며 모든 이상치를 표시하는 Tukey boxplot이 아니다. 기존 평균·최고값 표는 유지한다.
- Matchup: 타자 손잡이 또는 balls-strikes를 선택한다. 투구 수, 해당 상황의 구종 확인 투구 수, 사용률, 결과 확인 행 수, 스윙 수, 헛스윙 수, Whiff%를 표시한다. 사용률 분모와 Whiff% 분모는 다르다.
- Change: 제외 사유만 표시한다. 앱 관리 원시 영구 캐시가 없으며 과거 자료를 추가 조회하거나 DB migration을 하지 않는다. 기존 주력 패스트볼 구속 이력은 그대로 사용한다.

## 검증한 실제 데이터

2026-10-12에 Baseball Savant Statcast Search CSV의 MLBAM ID 669373, 조회 기간 2025-09-01~2025-09-07, 정규시즌 필터 응답을 확인했다. 응답은 2025-09-06 하루의 90개 투구다. `pitcher`는 전부 669373, `game_type`은 전부 R이다.

실제 확인 필드: pitch_type, game_date, release_speed, release_spin_rate, stand, balls, strikes, description, game_type. 모두 90/90 비결측이었다. 테스트 fixture는 실제 응답에서 필요한 컬럼과 기존 Arsenal 회귀에 필요한 delta_run_exp를 추출한 CSV이며 synthetic 자료가 아니다.

출처: https://baseballsavant.mlb.com/statcast_search/csv

조회 파라미터: all=true, type=details, player_type=pitcher, pitchers_lookup[]=669373, game_date_gt=2025-09-01, game_date_lt=2025-09-07, hfGT=R|.

한 선수·하루의 확인 결과를 모든 선수·시즌에 일반화하지 않는다. 실행 때 선수 ID, 시즌·경기 유형, 필수 컬럼, 유효한 숫자와 상황 값, 결측을 다시 검사한다. 정규시즌 R과 선택 시즌만 분석한다. 없는 필드는 미검증, 유효 데이터가 없으면 빈 상태를 표시한다. 릴리스·movement·위치·신장 필드는 이번 분석에 넣지 않았다. 인과·부상 위험·최적 메커니즘 판단은 제공하지 않는다.

## 표본과 결측

- 구종별 전체 투구 수와 지표별 유효 N·결측을 구분한다. 결측·비숫자·비유한 값·0 이하 구속/spin을 0으로 채우지 않고 제외한다.
- 표준편차는 유효 N>=2에서만 계산한다. Profile은 지표별 N<30이면 표본 부족이다.
- Matchup은 해당 상황의 구종 확인 투구를 사용률 분모로 사용하며, 결과 확인 행에서의 스윙을 Whiff% 분모로 사용한다. 스윙 0개면 Whiff%는 미계산이다.
- 상황 투구 N<30 또는 해당 구종 스윙 N<30이면 표본 부족이다. description 결측도 경고한다. 30은 베타 화면의 안내 기준이며 공식 유의성 기준이 아니다.
- 구종 미분류는 따로 집계한다. 잘못된 손잡이·카운트는 상황 집계에서 제외하며 유효 상황 N/전체 분류 투구 N을 표시한다.

## 조회와 호환성

StatcastService 내부의 두 항목 한도 메모리 캐시로 동일 선수·시즌·조회 범위를 공유한다. 기존 시즌 TTL을 재사용하며 동시 동일 조회를 잠금으로 합친다. 투수 지표·Arsenal·구속 이력·기간 조회·새 분석이 같은 raw를 재사용한다. UI와 PlayerBundle에는 raw DataFrame을 전달하지 않는다.

메모리 캐시는 앱 종료·재시작, TTL 만료, 두 항목 한도 초과 시 유지되지 않는다. 따라서 원시 캐시가 없는 실행에서는 새 분석이 시즌 원시 조회 1회 필요할 수 있다. 이는 pybaseball 고수준 호출 수이며 내부 HTTP 요청 수를 보장하지 않는다. 기존 SQLite 요약만으로 분포를 복원하지 않는다. 새 디스크 raw 캐시, DB schema 변경, 자동 이관은 없다. 큰 과거 재수집 루프는 구현하지 않았다.

새 분석은 버튼을 눌렀을 때 기존 TaskThread에서 로딩·집계한다. 선수 ID·시즌·선수 요청 generation이 달라지면 결과를 버린다. 분석 실패는 기존 선수 데이터를 비우지 않는다. 타자 화면에서는 분석 영역을 숨긴다. install.bat/run.bat 및 개인 DB·설정은 수정하지 않는다.

## 적용과 복구

1. 앱을 종료하고 기존 프로젝트 폴더 및 별도로 지정한 데이터 폴더를 백업한다.
2. ZIP의 `patch/payload/` 안의 내용을 `main.py`가 있는 프로젝트 폴더에 복사한다. 폴더를 합치고 같은 파일만 교체한다. 개별 UI 파일만 복사하지 않는다.
3. 기준 커밋 이후 해당 파일을 직접 수정했다면 먼저 `patch/update.patch`와 manifest의 기준 파일 SHA를 비교한다. 다른 버전 위에 무조건 덮어쓰지 않는다.
4. 기존 환경에서 `python -m compileall -q .`, `python -m pytest -q`를 실행하고 run.bat으로 시작한다. 새 의존성은 없다.
5. 복구는 앱 종료 후 백업한 소스 파일을 복원한다. 새로 추가한 분석 서비스·위젯·테스트·fixture·가이드는 제거할 수 있다. 사용자 DB·캐시 폴더를 삭제하지 않는다.

## 검증과 한계

최종 검증 결과는 ZIP의 VERIFICATION_KO.txt에 기록한다. 네트워크 테스트는 추가하지 않았다. 실제 응답 확인은 별도 수동 조회이고 회귀 테스트는 보존한 CSV·임시 프로필을 사용한다.

현재 목표는 Windows 11이다. Linux Qt offscreen 테스트·렌더링은 Windows 파일 설치·실화면 검증을 대신하지 않는다. 기존 Matplotlib CJK 글꼴 경고와 시스템별 글꼴 차이가 있을 수 있다. 베타 적용 후 한글, 테마 변경, 좁은 창, 투수/타자 이동 및 같은 선수의 시즌 변경을 실제 Windows에서 확인한다.
