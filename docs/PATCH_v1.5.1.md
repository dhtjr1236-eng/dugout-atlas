## C. 실제 데이터 요청 방식

- endpoint: `https://www.fangraphs.com/api/leaders/major-league/data`
- 응답: `data[]`에서 검증된 ID의 행 → `WAR`.
- `season=season1=선택연도`, `startdate=MLB 정규시즌 시작일`, `enddate=D`.
- `stats=bat/pit`, `month=1000`, `ind=0`, `team=0`, `qual=0`, `type=8`.
- 기존 `_api_params` 그대로 사용. `postseason=""`은 기존 정규시즌 모드이며 MLB 축에서 R 경기만 선택합니다.
- 전체 리더보드 응답에서 ID로 선택합니다. 이름 문자열로 확정하거나 팀별 split를 더하지 않습니다.
- 시즌 총계 응답을 선수 ID 검증에만 사용합니다. 그 WAR를 레이스 포인트로 사용하지 않습니다.
- 매 로딩 시 일정 조회 1건 + 선수 ID 검증 최대 2건이 범위 조회 전에 발생합니다.
- 범위 요청 수는 고유 선수·역할 × 표본 날짜 수에서 캐시 적중 수를 뺀 값입니다. UI의 `0/N`은 이 범위 요청 수이며 내부 HTTP 재시도 횟수는 별도입니다.
- 2025 일정 fixture 기준 공통 완료 날짜 184개, Preview 28개. 서로 다른 선수 2명은 Preview 최대 56건, Full detail 최대 368건입니다.
- 캐시: SQLite `player_stats`, source=`fangraphs_race_v1`. MLBAM·시즌은 기존 컬럼, role 문자열에 bat/pit·FG ID·시작일·종료일·모드·버전을 포함합니다. payload에 `fetched_at`, 원래 params를 보존합니다.
- 현재 시즌 TTL 5분, 과거 시즌은 기존 `_cache_ttl_days` 정책. 긴 Full detail 중 Preview TTL이 만료되면 일부 재조회할 수 있습니다.
- 전역 직렬 lock과 lock 안의 재캐시 확인으로 같은 성공 포인트의 동시 중복 요청을 막습니다. 요청 후 1초 대기. 무제한 병렬화하지 않습니다.
- 기존 FanGraphs 제한 재시도: 기본 최대 3회, timeout 20초, backoff 1·2초. 403/429는 즉시 중단하고 레이스 요청에 60초 cooldown을 적용합니다. 접근 제한을 우회하는 대체 경로는 추가하지 않았습니다.

## D. UI 동작

- 메인 → 심화 비교 → A/B 검색 → 시즌 레이스. C/D 슬롯은 기존 표에서 계속 사용됩니다.
- bat/pit 역할은 두 개의 드롭다운으로 명시합니다. 투타 겸업은 원하는 역할을 사용자가 확인하고 선택합니다. 합산하지 않습니다.
- Preview는 7번째 공식 날짜마다, 마지막 날짜를 추가해 실제 요청합니다. Full detail은 전체 날짜를 대상으로 캐시를 재사용합니다.
- 데이터 마커·tooltip·현재 WAR·최고점·fog는 원본 포인트만 사용합니다. WAR 하락이 있으면 선과 얼굴의 Y 위치도 하락합니다.
- 슬라이더가 미조회 날짜를 가리키면 두 선수별 `조회 포인트 없음`을 표시합니다. 얼굴은 마지막 조회 좌표에 남지만 그 값을 현재 날짜의 수치로 재표시하지 않습니다.
- 둘은 하나의 날짜 슬라이더와 타이머로 함께 진행하고 종료합니다. 데이터가 없는 첫날에 가짜 0 WAR를 만들지 않습니다.
- 최고점은 조회된 포인트 중 최대값. 동률은 최초 날짜. 한 재생 주기에서 선수별 금색 효과는 한 번, 처음부터 재생 시 초기화됩니다.
- fog는 직전 관측 local peak에서 0.5 WAR 이상 감소한 실제 포인트에서만 나타납니다. 효과 OFF에서도 재생·슬라이더·수치가 작동합니다.
- 시연은 별도 창이며 항상 `가상 데이터 시연`으로 표시합니다. 실제 캐시에 기록하지 않습니다.
- PNG/JPEG는 현재 선택 날짜의 정지 화면이며 GIF/MP4가 아닙니다.

## F. 남은 제약

- FanGraphs custom-range WAR는 **현재 반환값**이며 과거 발표 당시의 역사적 스냅샷이 아닙니다.
- 일부 수비 구성 요소는 기간별 계산 특성 때문에 부분 범위 WAR의 합과 시즌 최종 WAR가 다를 수 있습니다. 앱은 WAR를 재계산하지 않습니다.
- 요청서의 gameDate 규칙에 따라 `gameDate[:10]`을 공통 날짜로 사용하고 시간대 변환하지 않습니다. MLB `officialDate`와 UTC gameDate 날짜가 다른 야간 경기는 서로 다른 달력 날짜 의미가 있을 수 있습니다. 요청 D와 UI D는 같지만 이 축을 구장 현지일 또는 FanGraphs 자체 경기일과 같다고 보장하지 않습니다.
- 현재 UTC 날짜 자체는 제외합니다. 완료 시점이 모호한 당일 포인트를 보수적으로 생략하며, 같은 날짜에 미완료 경기가 있으면 해당 날짜를 제외합니다.
- FanGraphs ID가 없는 선수, 서로 모순되는 ID, 팀 split 중복은 실패 처리합니다. 누락 WAR를 0으로 만들지 않습니다.
- 휴식일/미조회일을 새 포인트로 생성하지 않습니다. 시각적 연결선만 존재합니다.
- 취소는 진행 중 HTTP 소켓을 강제 종료하지 않습니다. 새 작업을 막고 늦은 결과를 무시하며, 이미 실행 중인 요청은 timeout/제한된 retry 후 종료됩니다. 앱 종료도 안전한 worker 정리를 기다립니다.
- 중복 방지는 성공 캐시 포인트 기준입니다. 값이 없는 응답은 실데이터 캐시에 저장하지 않으므로 이후 사용자가 다시 시도하면 재조회할 수 있습니다.
- 서버의 지역·접속 정책 또는 403/429가 바뀌면 현재 A 검증의 미래 성공을 보장하지 않습니다.
