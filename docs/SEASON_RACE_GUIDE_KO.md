# 시즌 레이스 상세 적용·사용·추가 개발 가이드

대상: Dugout Atlas v1.5 → v1.5.1 로컬 패치. 기준 커밋 `892831235608ddd858eb5e2cf6d0338487304d05`.
앱 소스 패치이며 독립 실행형 EXE 설치 파일이 아닙니다. Windows 11 / Python 3.12+를 대상으로 합니다.

## 1. 패치 적용 전

1. Dugout Atlas를 종료합니다. 진행 중 조회가 있으면 취소하고 종료될 때까지 기다립니다.
2. 기존 프로젝트 폴더와 설정한 데이터 폴더를 별도로 백업합니다. 새 패치는 SQLite 스키마를 바꾸지 않고 다른 출처의 기존 데이터를 삭제하지 않습니다.
3. 패치 ZIP을 프로젝트 밖에 압축 해제합니다. 내부 `payload`는 덮어쓸 소스, `manifest.json`은 적용 전후 해시, `.patch`는 Git diff입니다.
4. 기준 버전이 다르거나 자체 수정이 있으면 적용기가 중단합니다. 경고를 무시하고 강제 덮어쓰기하지 말고 diff를 비교·병합해야 합니다.

## 2. Windows에서 적용

예시: 기존 프로젝트 `C:\Apps\dugout-atlas`, 패치 압축 해제 위치 `C:\Downloads\dugout-atlas-season-race-patch`.
PowerShell에서 실행합니다.

```powershell
cd C:\Downloads\dugout-atlas-season-race-patch
py -3 apply_patch.py --target "C:\Apps\dugout-atlas" --check
py -3 apply_patch.py --target "C:\Apps\dugout-atlas"
```

`--check`는 소스 파일을 수정하지 않습니다. 실제 적용 시 바뀌는 기존 파일과 복구 명세를 자동 백업합니다.
성공하면 백업 폴더 경로가 표시됩니다. 이미 같은 패치가 적용된 상태면 다시 덮어쓰지 않습니다.
`apply_patch.bat`을 더블클릭하고 프로젝트 경로를 입력해도 됩니다. Python Launcher가 없는 경우 `py -3` 대신 설치된 `python` 또는 프로젝트 `.venv\Scripts\python.exe`를 사용합니다.

패치 후 실행:

```powershell
cd C:\Apps\dugout-atlas
.\.venv\Scripts\python.exe -m compileall -q config services ui workers tools
.\.venv\Scripts\python.exe -m pytest -q
.\run.bat
```

기존 가상환경이 없다면 먼저 프로젝트의 `install.bat`으로 기존 요구사항을 설치합니다. 이 패치는 추가 라이브러리를 요구하지 않습니다.

## 3. Git으로 적용하는 경우

작업 중 변경이 없는 별도 브랜치에서 적용하세요. 아래 과정에는 commit/push/merge가 없습니다.

```powershell
git status --short
git switch -c feature/season-race-local
git apply --check "C:\Downloads\dugout-atlas-season-race-patch\dugout_atlas_1.5.1.patch"
git apply "C:\Downloads\dugout-atlas-season-race-patch\dugout_atlas_1.5.1.patch"
```

적용기와 `git apply` 중 하나만 선택합니다. main 반영과 release는 검토 후 별도로 결정합니다.

## 4. 복구

적용기가 출력한 백업 경로를 사용합니다. 패치 후 소스를 다시 수정했다면 복구기는 그 변경을 보호하기 위해 중단합니다.

```powershell
py -3 apply_patch.py --target "C:\Apps\dugout-atlas" --rollback "C:\Apps\dugout-atlas\season-race-backup-시간값"
```

복구는 패치로 변경한 파일만 되돌립니다. 새 SQLite 캐시 행은 남지만 이전 앱 동작을 바꾸지 않습니다. 필요하면 Settings → FanGraphs 캐시 삭제로 정리합니다.
Git 방식은 `git apply -R --check 패치경로`로 확인 후 `git apply -R 패치경로`로 복구할 수 있습니다. 관련 파일에 별도 수정이 있으면 먼저 보존하세요.

## 5. 실제 데이터로 사용

1. 앱 상단 **심화 비교**를 열고 시즌을 선택합니다.
2. 선수 A와 B를 자동완성 결과에서 선택합니다. 검색 결과의 `MLBAM ID`로 동명이인을 구분할 수 있습니다.
3. **시즌 레이스** 탭에서 A/B 역할을 확인합니다. 투타 겸업은 타격·투구 중 하나를 명시적으로 선택합니다.
4. **Preview / 저빈도 조회**를 눌러 일부 공식 날짜만 실제 조회합니다. 이 상태는 일별 전체 조회 결과가 아닙니다.
5. 필요하면 **Full detail / 전체 조회**를 누릅니다. 남아 있는 날짜를 순서대로 조회하며 성공한 캐시를 재사용합니다.
6. 로딩이 끝나면 재생/일시정지, 처음부터, 0.5×~4× 속도와 날짜 슬라이더를 사용합니다.
7. `조회 포인트 없음`은 해당 날짜에 받은 WAR가 없다는 뜻입니다. 데이터가 없는 값을 0 또는 추정값으로 표시하지 않습니다.
8. 점 위에 마우스를 놓으면 실제 날짜·WAR를 볼 수 있습니다. 최고점 레이블은 읽기 쉽게 소수 3자리지만 하단 현재 수치와 tooltip은 저장한 원본 float 값을 표시합니다.
9. **현재 화면 PNG/JPEG 저장**은 선택 날짜의 화면만 저장합니다. 영상이나 GIF는 생성하지 않습니다.

C/D 슬롯을 추가한 경우 기존 비교 표에는 함께 표시되지만 시즌 레이스는 A/B만 사용합니다.
선수·역할·시즌 변경, 탭 이동, 창 닫기는 레이스 작업을 취소합니다. 중간 성공 캐시는 유지됩니다.

## 6. 요청 수와 기다림

2025년 일정 검증 기준 공통 완료 날짜 184개, Preview 28개입니다.
두 명이면 최대 범위 요청은 Preview 56건, Full detail 368건입니다. 추가로 일정 1건과 ID 검증 최대 2건이 먼저 필요합니다.
UI `최대 범위 요청 / 캐시 적중 / 완료 수 ÷ 신규 수`를 확인하세요. 신규 수는 최초 예상치이며 각 HTTP 내부 재시도는 별도입니다.
요청마다 최소 1초 대기와 서버 응답 시간이 필요하므로 Full detail은 수분 이상 걸릴 수 있습니다. 빠른 확인은 Preview를 사용하세요.

- 현재 시즌 캐시 TTL은 5분입니다. 과거 시즌은 기존 정책을 따릅니다.
- Full detail은 캐시 범위를 읽고 누락된 날짜만 요청합니다. 캐시 TTL이 지났다면 재조회합니다.
- 403/429는 즉시 실패 처리하고 60초 대기 상태로 전환합니다. 계속 버튼을 누르지 말고 잠시 후 다시 시도하세요.
- 취소 후 현재 HTTP 요청이 반환될 때까지 새 조회 버튼이 잠시 비활성일 수 있습니다. UI 이벤트 루프는 유지됩니다.
- Settings의 출처별 새로고침/캐시 삭제는 먼저 레이스 조회를 취소하고 종료된 후 실행하세요.

## 7. 값의 의미와 날짜 해석

표시값은 `선택 시즌 정규시즌 시작일 ~ D` 범위에 대해 FanGraphs가 **현재 반환하는 WAR**입니다.
당시 그 날짜에 발표되었던 값을 저장한 역사적 스냅샷이 아닙니다. 이후 데이터 수정으로 같은 범위 값이 바뀔 수 있습니다.
경기별 WAR를 합산하거나 최종 WAR를 배분하지 않습니다. bWAR는 이 레이스에서 사용하지 않습니다.
수비 가치 등 기간 단위 처리 특성 때문에 부분 범위들의 합이 시즌 최종 WAR와 다를 수 있습니다.

공통 축은 MLB 일정의 R 경기만 사용하며 시즌 날짜를 4~9월로 고정하지 않습니다.
요청서의 gameDate 기준을 그대로 적용해 문자열 `gameDate[:10]`을 사용합니다. 시스템 현지 시간으로 변환하지 않습니다.
**주의:** `gameDate`는 UTC 시각이므로 미국 야간 경기의 MLB `officialDate`와 다를 수 있습니다. UI와 FanGraphs 요청의 D는 항상 동일하지만 구장 현지일과 일치한다고 해석하면 안 됩니다.
앱은 당일 진행 중인 기록 혼합을 피하기 위해 현재 UTC 날짜와 미완료 경기일을 생략합니다. 따라서 실시간 당일 누적 레이스가 아닙니다.

시각적 연결선은 연속 표시를 위한 것이며, 실제 데이터 포인트는 FanGraphs 범위 요청에 성공한 날짜만 의미합니다.
슬라이더가 미조회 날짜를 선택하면 숫자를 보간하지 않습니다. 얼굴은 이전 관측 위치에 남고 숫자는 미조회 상태입니다.

## 8. 최고점·하락 효과

- 최고점은 조회된 시계열에서 최대 WAR입니다. Preview 최고점은 아직 전체 시즌 최고점이라고 단정할 수 없습니다.
- 같은 최대값이면 최초 도달 날짜를 사용합니다. 선수당 한 재생 주기에 한 번 금색 효과를 냅니다.
- 처음부터 재생하면 이벤트 기억을 초기화합니다. 한 선수만 시간축에 남아 멈추지 않습니다.
- fog는 최근 관측 local peak 대비 0.5 WAR 이상 하락했을 때만 표시됩니다. 낮은 시즌 초 WAR 자체로는 발생하지 않습니다.
- 애니메이션 효과 끄기는 sparkle/fog를 숨깁니다. 수치·마커·슬라이더·재생은 유지됩니다.
- 캐릭터는 코드로 그린 기본 얼굴입니다. 실제 사진 다운로드는 하지 않습니다. 좌표의 프레임 사이 부드러운 이동 보간은 이 패치에 포함하지 않았습니다.

## 9. 가상 데이터 시연

시즌 레이스의 **가상 데이터 시연** 버튼은 별도 창을 엽니다. 실제 탭에 시연 포인트를 섞지 않습니다.
선택 시즌의 실제 MLB 일정만 사용하고, 6월·9월의 완료 날짜가 있어야 합니다.
A는 6월 1.8 최고점 → 시즌 마지막 0.9, B는 같은 6월 1.2 → 9월 3.1 최고점입니다.
이는 테스트용 시나리오이며 선수 실명·실제 캐시와 무관합니다. 네 개의 가상 포인트만 표시하며 중간 날짜를 일별 기록으로 만들지 않습니다.
현재 시즌에 아직 9월 완료 날짜가 없다면 2025 등 완료 시즌을 선택하세요.

## 10. 실제 API 재검증 도구

```powershell
.\.venv\Scripts\python.exe tools\verify_season_race.py --output race-evidence.json
```

네 개 범위 요청과 MLB 일정 조회를 수행합니다. JSON에는 endpoint, ID, 역할, start/end, 원본 선수 행, 반환 WAR, 화면용 표현과 일치 여부가 기록됩니다.
성공 시 `Availability: A`, 종료코드 0입니다. 실패하면 `UNVERIFIED`, 오류 메시지와 종료코드 1입니다.
네트워크 실패만으로 B/C라고 단정하지 않습니다. 더 성긴 범위만 검증되면 B, 시즌 총계만 가능하다는 별도 증거가 있을 때 C로 판단해야 합니다.
오류 JSON을 공유할 때 인증정보를 추가하지 마세요. 도구는 토큰·브라우저 세션을 요구하지 않습니다.

## 12. 추가 개발 우선순위와 가이드라인

### P0 — 날짜 의미의 별도 검증

요청서가 gameDate calendar를 지정해 현재는 UTC 문자 날짜를 사용합니다.
미국 야간 경기, 더블헤더, 서스펜디드 경기 각각에 대해 MLB `officialDate`, `gameDate`, FanGraphs 범위 포함 경기를 대조하세요.
경기일 의미를 officialDate로 바꾸려면 규칙을 명시하고 캐시 버전을 올려 이전 날짜축과 혼용하지 않아야 합니다.
수치가 같다는 이유만으로 두 날짜 기준이 동등하다고 판정하지 마세요.

### P0 — Windows 네이티브 수용 테스트

Windows 11에서 A/B 검색, 테마·언어·큰 글자 크기, 조회 도중 시즌 전환·창 닫기·앱 종료를 실행하세요.
네트워크 timeout 동안 창이 응답하는지, 종료 중 `QThread destroyed while running`이 없는지 확인합니다.
한글·일본어 PNG/JPEG의 글리프, 사용자 지정 데이터 폴더, 쓰기 불가 저장 경로도 점검하세요.

### P1 — 완전한 단일 진행 요청 공유

현재 성공 포인트는 lock+cache로 중복을 막습니다. 향후 취소 가능한 shared-future 방식으로 확장하면 누락 응답도 짧은 기간 공유할 수 있습니다.
실패/누락 상태를 실제 WAR 캐시에 저장하지 말고 별도 상태 캐시로 관리하세요. 한 창의 취소가 다른 창의 필요한 요청을 끊지 않도록 구독자 수를 관리해야 합니다.

### P1 — 부드러운 좌표 애니메이션

QVariantAnimation 등으로 마지막 두 원본 포인트 사이의 화면 좌표만 이동시킬 수 있습니다.
숫자·tooltip·캐시·최고점·fog는 원본 포인트만 사용합니다. 보간된 좌표에 실제 fWAR 숫자를 붙이지 않습니다.
Animation OFF에서는 보간도 중단하고 실제 포인트로 즉시 이동시키세요.

### P1 — 진행 중 시즌의 확정 완료 시점

현재는 당일을 제외하는 보수적인 정책입니다. FanGraphs의 갱신 지연과 MLB 완료 상태를 실제로 비교해 확정 시점을 검증한 뒤 당일 값을 허용하세요.
일부 경기만 끝났는데 그 날짜 전체가 최종 확정됐다고 표시하지 않습니다.

### P2 — 더 긴 시계열·접근 정책 변경 대응

Full detail의 요청 수·총 소요시간·429 빈도를 기록해 합리적인 간격을 조정하세요. 무제한 병렬 요청으로 해결하지 않습니다.
UI 상태는 부분 성공/취소/실패를 구분하고 공급처 오류를 숨기지 않습니다.
bWAR 레이스, GIF/MP4는 각각 별도 데이터·내보내기 검증 후 추가하세요.
