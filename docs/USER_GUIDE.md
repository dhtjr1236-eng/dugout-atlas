# Dugout Atlas 사용자 가이드

대상: v1.7 / Windows 11 / Python 3.12 이상. 과거 변경 내역은 [CHANGELOG](../CHANGELOG.md)에서 확인합니다.

## 설치·실행·업데이트

처음에는 프로젝트 전체를 압축 해제하고 `install.bat`, `run.bat` 순으로 실행합니다. `main.py`나 `config/paths.py`만 따로 옮기지 마세요. `paths.py`는 실행기가 아니라 경로를 계산하는 모듈입니다.

업데이트 전 앱을 종료하고 프로그램 폴더와 사용자 지정 데이터 폴더를 백업하세요. 직접 수정한 파일이 있다면 먼저 비교합니다. 새 폴더에서 실행할 경우 기본 데이터 위치도 달라질 수 있으며, 기존 데이터는 자동 복사되지 않습니다. 버전이 다른 덮어쓰기 패치를 임의로 적용하지 마세요.

## 기본 사용

1. 홈에서 분석할 시즌을 선택합니다. 즐겨찾기 선수 또는 분석 바로가기를 누릅니다.
2. 경기 화면에서는 날짜와 경기를 선택합니다. 타자·투수 이름을 누르면 해당 경기 시즌의 선수 분석으로 이동합니다.
3. 선수 검색 결과에서 선수를 선택하고 시즌을 확인합니다. 출처 상태와 조회 시각도 함께 확인하세요.
4. 비교 화면에서 선수를 추가합니다. 심화 비교의 Season Race는 두 선수와 역할을 선택한 뒤 실행합니다.

[홈 상세 설명](OFFSEASON_HOME_GUIDE_KO.md) · [시즌 레이스 상세 설명](SEASON_RACE_V161_GUIDE_KO.md)

홈의 기록 수는 로컬 DB 보유 현황입니다. 조회 실패, 자료 없음, 실제 기록 0은 서로 다릅니다. 경기 없는 하루를 시즌 종료로 판단하지 않습니다.

## 설정

설정에서 언어(한국어/영어/일본어), 밝은·어두운 테마와 강조색, 글자 크기, 자동갱신 간격, 알림을 바꿀 수 있습니다. 캐시와 데이터 위치 작업은 진행 중인 조회가 끝난 뒤 실행하세요.

- **캐시 관리:** 앱 설정에서 삭제하거나 소스별 새로고침을 선택합니다. 사용자 데이터 위치를 인식하는 앱 기능을 사용하세요.
- **데이터 위치:** 소스 실행에서는 새 빈 폴더로 데이터를 복사하고 재시작 후 새 위치를 적용합니다. 기존 자료를 삭제하는 자동 이관은 하지 않습니다.
- **진단정보:** 앱·Python·의존성 및 소스 상태 확인에 사용합니다.

`clear_cache.bat`은 이제 설정 화면 이용 방법만 안내합니다. DB를 직접 삭제하지 않습니다. `cache/`와 `database/` 폴더에는 Python 코드가 있으므로 통째로 지우지 마세요.

## 실제 저장 위치

| 항목 | 소스 실행의 위치 |
| --- | --- |
| DB | 설정한 데이터 루트의 `data/mlb_advanced_gameday.sqlite3` |
| 다운로드 캐시·사진 | 데이터 루트의 `cache/` |
| 로그 | 데이터 루트의 `logs/dugout_atlas.log` |
| 기본 데이터 루트 | 별도 설정이 없으면 프로젝트 폴더 |
| 사용자 이름 override | `%LOCALAPPDATA%\Dugout Atlas\config\player_names_override.json` |
| 기본 내보내기 폴더 | `%LOCALAPPDATA%\Dugout Atlas\exports` |

Windows 소스 실행의 일반 설정은 기존 QSettings를 유지합니다. LOCALAPPDATA가 없으면 홈 폴더 아래 fallback을 사용합니다. frozen 실행 경로는 [패키징 준비 안내](WINDOWS_PACKAGING_GUIDE_KO.md)를 확인하세요. 아직 설치형 배포 검증 전입니다.

## 선수 이름 수정

기본 이름은 `config/player_names_seed.json`에 있습니다. 사용자 변경은 위 override 경로에 UTF-8 JSON으로 저장하면 업데이트 시 기본 파일과 분리해 관리할 수 있습니다.

```json
{
  "players": [
    {"en": "Shohei Ohtani", "ko": "오타니 쇼헤이", "ja": "大谷翔平"}
  ]
}
```

`en`은 기본 선수 이름과 대응하는 영문 이름입니다. `ko`, `ja`에는 원하는 표시명을 적습니다. 수정 후 앱을 재시작하세요. override가 없으면 기본 이름을 사용하고, JSON이나 구조가 잘못되면 경고 로그를 남기고 기본값으로 돌아갑니다. 이름은 표시용이며 통계 조회의 선수 ID를 바꾸지 않습니다.

## Baseball-Reference 자료 가져오기

1. 앱의 **B-Ref 다운로드**로 공식 데이터 디렉터리를 엽니다.
2. 공식 WAR ZIP 또는 TXT/CSV를 다운로드합니다.
3. **B-Ref 파일 가져오기**에서 파일을 선택합니다.

가져온 자료는 데이터 루트의 `data/bref/`에 저장되며 우선 사용됩니다. 파일에 없는 OPS+/ERA+는 비워 둡니다. 자동 요청이 403/429로 거절되면 반복 요청을 제한합니다. fWAR를 bWAR로 바꾸어 표시하지 않습니다.

## 문제 해결

| 증상 | 먼저 확인할 내용 |
| --- | --- |
| PyQt6 등 모듈을 찾지 못함 | `install.bat` 실행 여부, `run.bat`으로 같은 가상환경을 사용하는지 |
| 경기 목록이 비어 있음 | 선택 날짜, 조회 상태, 인터넷 연결 |
| 특정 출처만 비어 있음 | 선수·시즌, 출처 상태, 제공처 접근 제한 또는 자료 누락 |
| 예전 기록처럼 보임 | 출처별 새로고침 사용, 제공처 자체 갱신 시점 |
| 최초 조회가 오래 걸림 | 시즌 데이터 수집 대기; 레이스는 월간부터 시작 |
| 이전 DB가 안 보임 | 설정된 데이터 위치와 이전 실행 폴더 비교; 초기화하지 말 것 |

`run_debug.bat`으로 콘솔 메시지를 확인하고 설정된 데이터 루트의 로그를 확인하세요. `diagnose_sources.bat`은 실제 외부 조회를 수행할 수 있는 진단 도구입니다. 개인정보와 개인 경로를 확인한 뒤 로그를 공유하세요.

개발 검증은 `verify.bat` 또는 프로젝트 가상환경의 `python -m pytest -q`로 수행합니다. 자세한 코드 구조와 수정 원칙은 [ARCHITECTURE](../ARCHITECTURE.md)를 참고하세요.
