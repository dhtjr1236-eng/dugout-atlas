# OPS 시즌 레이스·애니메이션 사용 가이드

대상: Dugout Atlas v1.8 / Windows 11 / Python 3.12 이상.

## 추가된 기능

- Season Race의 지표 메뉴에서 **fWAR · FanGraphs / OPS · MLB**를 선택합니다.
- OPS는 MLBAM ID로 경기별 타격 기록을 확보하고 로컬에서 누적 계산합니다.
- 선수별 OPS·타석 수(PA)·OBP·SLG·마지막 출전일, 두 선수의 OPS 차이와 우위 선수를 표시합니다.
- 50타석 미만이면 적은 표본임을 안내합니다. 50타석은 이 화면의 설명용 기준이며 규정타석 기준이 아닙니다.
- 재생 중 세로축 범위를 고정합니다. 마커가 겹치지 않도록 실제 값과 마커를 연결선으로 연결합니다.
- 간격과 표시 기간 변경은 이미 확보한 기록에서 처리합니다. 다시 네트워크를 요청하지 않습니다.
- fWAR의 조회 방식·요청 간격·쿨다운·캐시 키는 유지합니다.

## 설치와 업데이트

[사용자 가이드](USER_GUIDE.md)와 README의 소스 설치 순서를 따릅니다. 기존 앱과 별도로 선택한 데이터 폴더를 먼저 백업하세요. 기존 v1.7 검토용 payload를 v1.8 위에 다시 덮어쓰지 마세요. 새 소스의 관련 파일을 함께 사용해야 하며 `ui/season_race_view.py`만 교체해서는 안 됩니다.

기존 DB·캐시·QSettings 및 데이터 폴더 선택을 유지합니다. 새 폴더에서 실행하면 기본 데이터 위치가 달라질 수 있으므로 설정에서 기존 위치를 확인하세요. 소스 복구는 백업한 소스 파일을 복원하며 사용자 DB를 삭제하지 않습니다.

## 사용 순서

1. 비교 화면에서 **심화 비교**를 엽니다.
2. 선수 A·B와 시즌을 고릅니다. 레이스는 A/B 두 슬롯을 사용합니다.
3. **Season Race → OPS · MLB**를 선택합니다.
4. 두 역할을 **타격**으로 선택합니다. 투타 겸업 선수도 타격으로 선택해야 합니다.
5. `샘플 불러오기`를 누릅니다. 처음에는 완료 경기 확인 → 경기 기록 조회 → 누적 계산 순서로 진행합니다.
6. 로딩이 끝나면 마지막 날짜의 값을 먼저 보여 줍니다. `처음부터`와 `재생`으로 시즌을 따라갈 수 있습니다.
7. 월간·격주·주간·전체 조회 또는 기간을 바꿔 보세요. OPS 기록이 준비된 상태에서는 즉시 로컬에서 다시 표시합니다.
8. 최신 원본을 다시 확인하려면 `샘플 불러오기`를 누릅니다. 유효 캐시는 재사용합니다. 필요하면 설정의 MLB 소스별 새로고침으로 OPS 캐시를 지운 뒤 다시 불러옵니다.

## 속도와 캐시

서로 다른 두 타자의 캐시가 없는 정상 응답 기준으로 일정 1회 + 선수별 경기 기록 1회, 보통 총 3회 요청합니다. 이 수치는 레이스의 OPS 조회 경로만 뜻하며 앱의 다른 조회나 사진 다운로드는 별도입니다. 통신 시간은 네트워크 상태에 따라 달라집니다.

선수 원본 경기 기록은 SQLite `mlb_ops_game_log_v1` / `bat:R`에 저장합니다. 기존 공통 정책을 재사용해 현재 시즌은 1시간, 과거 시즌은 30일 TTL을 사용합니다. 일정은 같은 레이스 서비스 인스턴스 안에서만 메모리에 재사용합니다. 일정의 마지막 완료 날짜가 달라지면 선수 캐시가 남아 있어도 재확인합니다.

조회 간격 변경에는 네트워크 요청이 없습니다. fWAR를 선택하면 기존 FanGraphs 날짜별 조회 방식으로 돌아가므로 OPS와 같은 속도가 되지는 않습니다.

## 숫자를 읽는 법

누적 OPS는 경기별 OPS의 평균이 아닙니다. 해당 날짜까지의 경기별 원시 기록을 합산한 후 다음 식으로 계산합니다.

- OBP = (H + BB + HBP) / (AB + BB + HBP + SF)
- SLG = TB / AB
- OPS = OBP + SLG

BB에는 고의사구가 포함되므로 IBB를 다시 더하지 않습니다. 희생번트와 타격방해는 PA에는 포함될 수 있지만 위 OBP 분모에 임의로 넣지 않습니다. 타수가 0이거나 필요한 기록이 누락되면 OPS를 추정하지 않습니다.

카드의 값과 차이는 계산 원값을 기준으로 각각 반올림합니다. 따라서 화면의 반올림된 두 값을 직접 뺀 결과와 표시 차이가 마지막 자릿수에서 다를 수 있습니다. 반올림 전 값은 그래프 툴팁에서 확인할 수 있습니다.

기간을 7~8월로 지정해도 값은 시즌 시작부터 해당 날짜까지 누적 OPS입니다. 기간은 표시할 날짜만 제한합니다. 월간은 표시 범위의 월별 마지막 완료일, 격주는 14일 간격, 주간은 완료된 공식 경기 날짜 7개 간격입니다. 무출전일에는 누적값을 유지하며 마지막 출전일도 함께 표시합니다. 첫 출전 전에는 값을 만들지 않습니다.

## 범위와 제한

- 이번 구현은 **정규시즌 타격 OPS**입니다. 포스트시즌, 투수 피OPS, 홈런·안타 레이스는 포함하지 않습니다.
- 오늘(UTC)은 제외하고 완료된 경기로 계산합니다. MLB 공식 경기 날짜를 사용합니다.
- 연기된 일정은 제외하며 동일 경기 ID는 중복 합산하지 않습니다. 더블헤더는 다른 경기 ID의 두 경기를 모두 포함합니다.
- 중단 후 재개한 경기는 현재 정정된 기록을 공식 경기 날짜에 귀속합니다. 그 날짜 당시에 발표됐던 수치를 재현하는 타임머신은 아닙니다.
- 데이터 공급처가 누락한 개별 경기까지 완전성을 독립적으로 보장하지는 않습니다. 명시적 잘림·ID 불일치·필수 카운트 누락을 검출하면 오류로 중단합니다.
- 응답이 1,000개 이상이거나 전체 행 수와 불일치하면 불완전 응답으로 처리합니다. 부분 데이터를 정상 시즌 합계처럼 표시하지 않습니다.
- 첫 타석 부근의 OPS는 크게 튈 수 있어 전체 기간 축이 넓어질 수 있습니다. 후반기 기간을 지정하면 읽기 쉬워집니다.
- Windows 11 실환경 검증은 아직 필요합니다. Linux Qt offscreen 검증은 Windows 설치 검증과 다릅니다.

## 구현과 검증

OPS 계산은 `services/ops_race.py`, 축과 기간 최고·최저는 `services/race_presentation.py`, 애니메이션은 `services/race_animation.py`, 저장 옵션은 `ui/race_export_dialog.py`에 분리되어 있습니다. `ui/season_race_view.py`가 화면을 연결합니다.

회귀 검증은 `python -m compileall -q .`, `python -m pytest -q`로 수행합니다. 결과와 남은 제한은 [v1.8 패치노트](PATCH_v1.8.md)를 확인하세요. 새 테스트는 실제 네트워크를 호출하지 않습니다.

## OPS 축 범위와 기간 최고·최저

1. 시즌 레이스에서 `OPS · MLB`를 고르고 두 타자의 기록을 불러옵니다.
2. `OPS 축 범위 직접 지정`을 체크합니다. 예: 최솟값 `0.700`, 최댓값 `1.200`.
3. 체크를 해제하면 불러온 기간 전체의 자동 범위로 돌아갑니다. 재생 중에도 축 범위는 고정됩니다.
4. 최솟값이 최댓값 이상이면 입력값을 안전하게 조정합니다. 입력 가능 범위는 0~5이며 최소 간격은 0.001입니다.
5. 범위 밖 기록은 그래프 가장자리의 삼각형과 실제 수치로 표시합니다. 카드의 수치는 바뀌지 않습니다. 축을 좁히면 시각적 차이가 확대된다는 점을 고려하세요.
6. A/B의 기간 최고·최저와 날짜가 카드 아래 표시됩니다. 기간 지정이 켜져 있으면 해당 기간, 꺼져 있으면 불러온 전체 기간을 사용합니다. 월별/주별 표시라도 확보된 일별 OPS 전체에서 최고·최저를 찾으며, 동률은 가장 이른 날짜를 표시합니다.

## GIF / WebP 저장

1. 기록을 불러온 뒤 `움직이는 이미지 저장`을 누릅니다. OPS와 기존 fWAR 모두 가능합니다.
2. 시작·종료 날짜, GIF/WebP, 재생 길이(6~12초), 초당 프레임(5/10), 해상도(640×360 또는 960×540), 반복 여부를 선택합니다.
3. 저장 위치를 정합니다. 기본 제안 위치는 앱의 사용자 exports 폴더입니다.
4. 프레임 생성 진행률이 표시되고, 마지막에는 이미지 압축 상태로 바뀝니다. 화면 위 `취소` 버튼으로 중단할 수 있습니다. 창을 닫아도 취소합니다.
5. 완료 문구를 확인하고 파일을 여세요. 실패·취소 때는 기존 동명 파일을 유지하며 임시 파일을 정리합니다. 저장 성공 때만 사용자가 선택한 파일을 교체합니다.

추가 네트워크 요청 없이 이미 불러온 표본만 저장합니다. 내보내는 날짜 범위가 달라져도 OPS의 시즌 누적 계산 시작점은 바뀌지 않습니다. 자동/직접 지정된 현재 축을 저장 시작 시 고정하고, 내보내기 기간의 최고·최저는 그 기간의 일별 기록으로 계산합니다. 짧은 날짜 구간은 동일 장면이 반복될 수 있고 인코더가 중복 프레임을 합칠 수 있습니다.

애니메이션은 창 전체 녹화가 아닌 별도의 차트 구성입니다. 현재 수치·날짜·기간 최고/최저·출처를 포함하고, 헬멧/얼굴 대신 간결한 컬러 마커를 사용합니다. UI의 재생 배속과 저장 파일의 재생 길이는 별개입니다. 저장 중 화면 축을 바꿔도 시작 시 복사한 값으로 저장합니다. Pillow 빌드가 WebP를 지원하지 않으면 GIF만 표시합니다.

렌더링과 압축은 Qt GUI와 분리한 프로세스에서 수행합니다. 최대 120프레임으로 제한했지만 고해상도 저장에는 일시적으로 수백 MB 메모리가 필요할 수 있습니다. 느린 PC에서는 640×360 / 5 fps를 선택하세요. Windows 11의 실제 파일 선택창·취소·종료 및 배포 EXE 환경은 별도 확인이 필요합니다.

README의 [OPS_example.gif](images/OPS_example.gif)는 **예시 선수 A/B의 가상 데이터**를 실제 구현으로 저장한 기존 원본입니다. 실제 선수 성적이 아니며 사용자 DB에 예시 자료를 쓰지 않았습니다.

`main.py`에는 Windows 자식 프로세스 시작을 위한 `freeze_support()`가 포함됩니다. Windows 11 실환경 검증과 EXE 배포 검증은 별도로 필요합니다.
