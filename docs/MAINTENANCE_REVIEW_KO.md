# 2026-10-03 기존 기능 복원 및 유지보수 검토

## 인정하는 한계

이전 179개 테스트 통과는 Windows 실사용·패키징·기존 데이터 호환성을 보장하지 않는다. 저장소 변경은 사용자 PC에 자동 반영되지 않는다. 사용자 PC 데이터가 손상되었다는 증거는 없지만, 준비안의 경로 전환으로 기존 자료가 사라진 것처럼 보일 수 있었다.

## 복원 및 수정

- 소스 실행의 QSettings와 기존 data_root/data 구조 복원. 신규 빈 DB로 전환되던 회귀를 줄인다.
- 폴더 선택 기능 복원. 이전 setEnabled(False)는 주기적 _update_busy에서 다시 켜져 실제로는 변경이 가능한데 재시작 시 무시되는 불일치도 있었다.
- 선수명 override 경로 계산 시 폴더를 만들지 않아 import 시 불필요한 쓰기 제거.
- 프로젝트 import를 main 내부로 이동해 경로 접근 오류가 시작 오류 처리 범위에 들어오도록 조정.
- 다른 로그 handler가 있어도 자체 파일 handler를 등록하고 반복 설정 시 중복 생성 방지.
- 데이터 삭제·이동·자동 마이그레이션은 수행하지 않는다.

## 유지보수 우선순위

1. P0: 기존 DB·설정 보존을 실제 Windows 업그레이드 시나리오로 확인. 정상/권한거부/손상파일/취소 후 재실행 회귀 테스트.
2. P1: 데이터 정확성. MLBAM ID 매칭, 결측 WAR 유지, 소스 오류·표본 부족 표시 검증. 접근 차단을 우회하기 위한 무리한 재요청은 추가하지 않는다.
3. P1: 비동기 안정성. 조회 전환 시 오래된 응답 무시, 종료 시 worker 정리, 중복 요청과 타이머 경합을 측정하고 필요 부분만 수정.
4. P2: 계측 후 최적화. 시작 시간, 네트워크 시간, SQLite 읽기, 그래프 재그리기 시간을 나눠 측정. 병목이 확인된 중복 작업만 줄이고 TTL·공식 데이터 계산은 유지.
5. P2: 운영 문서. 오류 상황별 해결법과 로그 수집 방법, 의존성 검증 조합, 변경 파일 목록 및 일괄 적용 패키지를 준비.
6. P3: 안정화 후 패키징. Windows onedir 실기 확인 다음에 Inno Setup 진행.

기능 추가·전면 리팩터링·웹 전환은 현재 유지보수 작업 범위가 아니다.
