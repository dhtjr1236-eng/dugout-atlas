# Dugout Atlas v1.61 — 시즌 레이스 및 선수 탐색 가이드

이 문서는 v1.61에서 도입된 기능의 가이드입니다. 현재 버전은 **v1.7**이며 [최신 패치노트](PATCH_v1.7.md)를 우선 참고하세요. v1.6 기능 확장 미리보기의 세 기능을 통합했습니다.

## 설치 및 업데이트

1. 실행 중인 프로그램을 종료합니다.
2. [main 소스 ZIP](https://github.com/dhtjr1236-eng/dugout-atlas/archive/refs/heads/main.zip)을 내려받아 새 폴더에 풉니다.
3. Windows 11 / Python 3.12 이상에서 `install.bat`, 다음으로 `run.bat`을 실행합니다.
4. 기존 사용자 데이터 위치가 있다면 Settings에서 해당 데이터 경로를 사용합니다.

Git 사용자는 작업 내용을 보관한 뒤 `git pull --ff-only origin main`으로 갱신합니다.
의존성 설치: `python -m pip install -r requirements.txt -c constraints-release.txt`.
검증: `python -m pytest -q`. 실행: `python main.py`.

이전 미리보기 패치 ZIP은 당시 v1.6 기준 파일용입니다. v1.61 위에 다시 적용하지 않습니다.
현재 소스에는 사용자 선수명 파일과 축소된 기본 창 크기가 포함됩니다.

## 1. 경기에서 선수 분석으로 이동

- 현재 타자와 투수 버튼, 박스스코어 선수 행, 플레이별 기록의 타자·투수 이름을 클릭합니다.
- 라인업 화면의 선수 버튼도 같은 흐름을 사용합니다.
- 라인스코어 아래 득점 플레이의 득점자는 각각 별도 행으로 표시하고 선수 ID로 연결합니다. 한 플레이의 여러 득점자를 여러 행에 표시하므로 행별 타점을 합산하지 마세요.
- 선수 분석 탭으로 이동하며 표시 중인 경기의 시즌과 날짜를 사용합니다.
- 선수명은 매칭 키가 아닙니다. 정수 MLBAM ID를 사용하므로 이름이 같아도 다른 선수로 이동합니다.
- 팀별 이닝 점수·R/H/E는 팀 합계이므로 선수 링크가 없습니다.
- 응답이 늦은 이전 시즌 조회가 최신 선수 화면을 덮어쓰지 않도록 요청 세대를 검사합니다.

## 2. 시즌 레이스 샘플 선택

비교 화면에서 두 선수를 고른 다음 심화 비교의 Season Race에서 사용합니다.
기존 타격/투구 역할 선택은 유지됩니다. 오타니처럼 투타를 겸하는 선수도 역할별로 별도 조회합니다.

| 옵션 | 샘플 날짜 | 요청량 경향 |
| --- | --- | --- |
| 월간 | 선택 범위 내 매월 마지막 완료 경기일 | 선수당 약 6~7회 |
| 격주 | 첫 완료일 이후 14일 이상 지난 다음 완료일, 마지막 완료일 포함 | 선수당 약 13~15회, 시즌 길이에 따라 다름 |
| 주간 | 완료된 공식 경기 날짜 7개 간격, 마지막 완료일 포함 | 기존 Preview와 같은 방식 |
| 전체 상세 | 모든 완료된 공식 경기 날짜 | 선수당 약 180일 이상 가능 |

`기간 지정`을 켜면 시작·종료 월/일을 지정할 수 있습니다. 선택한 시즌의 날짜를 사용합니다.
한 달만 보려면 그 달의 시작일~말일을 선택합니다. 지정 범위에도 선택한 샘플 간격이 적용됩니다.
범위 내 모든 날짜를 원하면 `전체 상세`와 기간 지정을 함께 사용합니다.

**WAR는 항상 정규시즌 시작일~샘플 날짜의 FanGraphs 누적값입니다.**
범위 필터는 조회할 종료일을 줄일 뿐, 누적값의 시작일을 바꾸지 않습니다.
없는 값은 0으로 채우지 않고, 일별 WAR를 합산하거나 추정하지 않습니다.

### 요청량 계산과 확인창

1. 백그라운드에서 MLB 일정과 엄격한 MLBAM↔FanGraphs 매핑을 준비합니다.
   이 메타데이터 준비에는 MLB 일정 1회와 선수별 ID 확인 요청이 필요합니다.
2. 실제 날짜별 WAR 조회 전에 로컬 SQLite 캐시를 확인합니다.
3. 전체 작업 수, 캐시 적중, 신규 작업 수, 최소 예상 대기 시간을 표시합니다.
4. 전체 상세에서 신규 요청이 **50개를 초과**하면 확인창이 열립니다. `예`를 선택해야 날짜별 조회를 시작합니다.
   `아니요`, 닫기 또는 취소는 날짜별 조회를 시작하지 않습니다.

예상 시간 = 신규 요청 수 × 요청 간격(기본 1초)입니다. 통신 시간과 서버 응답 시간은 별도입니다.
예를 들어 신규 360개면 최소 360초이며 실제 완료는 더 오래 걸릴 수 있습니다.
확인창은 `open()`을 사용하여 Qt 이벤트 루프를 막지 않습니다.
캐시 TTL이 확인 중 만료되어도, 계획에 포함된 캐시 스냅샷을 사용해 승인한 신규 요청 예산을 늘리지 않습니다.

403/429가 발생하면 현재 작업이 실패 상태로 멈추고 60초 쿨다운 동안 FanGraphs 추가 요청을 차단합니다.
시간이 지난 후 다시 불러오면 이미 성공한 값은 기존 `fangraphs_race_v1` 캐시를 재사용합니다.
현재 통신 요청 자체는 취소 시 즉시 강제 종료하지 않고, 제한된 통신 대기 후 취소를 반영합니다.

## 3. 선수 마커

- **벡터 헬멧**: 기본값. 챙·귀 보호대·명암·선수 이니셜을 포함합니다. 색상은 현재 테마의 강조색과 비교색을 따릅니다.
- **MLB 선수 사진**: MLBAM ID별 공식 이미지 주소에서 백그라운드로 다운로드합니다.
- 사진이 준비되기 전, 다운로드 실패, 오프라인, 잘못된 이미지 응답에는 즉시 헬멧을 사용합니다.
- 이미지는 32×32 원형 RGBA PNG로 저장됩니다.
- 기본 캐시: 프로젝트의 `cache/headshots/{mlbam_id}.png`.
  데이터 루트를 따로 지정했다면 그 루트의 `cache/headshots/`를 사용합니다.
- 같은 창에서 각 ID는 한 번만 시도하고, 저장된 사진은 다음 실행에도 재사용합니다.
  일시적인 실패 후 다시 시도하려면 프로그램을 다시 열어 주세요.
- 새 사진을 받고 싶다면 프로그램 종료 후 해당 ID의 PNG만 삭제합니다.
- Matplotlib의 DrawingArea/OffsetImage를 메모리에 유지하므로 슬라이더 조작 때마다 이미지 다운로드·디코딩·썸네일 생성은 반복하지 않습니다.

## 4. 직접 수정할 파일

| 경로 | 역할 |
| --- | --- |
| `config/player_names_seed.json` | 기존 EN/JA/KO 선수 이름 데이터 |
| `ui/game_view.py` | 선수 셀 UserRole, 클릭 신호, 경기 문맥 |
| `ui/main_window.py` | 선수 탭 이동 및 시즌 전달 |
| `controllers/app_controller.py` | 비동기 선수 조회와 오래된 응답 제외 |
| `services/live_scoring.py` | 득점자별 정확한 ID 연결 |
| `services/season_race.py` | 샘플 날짜, 로컬 계획, 조회 실행, 기존 WAR 캐시 |
| `ui/season_race_view.py` | 간격/기간 선택, 비차단 확인창, 사진 작업 관리 |
| `ui/character_renderer.py` | 헬멧 그림과 마커 메모리 캐시 |
| `services/headshots.py` | 기존 `base_http.async_get_bytes` 재사용, 이미지 검증/원형 처리 |
| `cache/file_cache.py` | 사진 경로 및 원자적 저장 |
| `config/translations.json` | 추가 EN/KO/JA UI 문구 |

`services/base_http.py`는 기존 타임아웃·응답 크기 제한 기능을 재사용하므로 수정하지 않았습니다.

## 5. 검증 및 한계

- 기능 확장 검증: 기존 133개와 신규 14개, 총 **147 passed**. v1.61은 버전 일치 회귀 검사도 추가했습니다.
- 신규 파일: `test_game_player_navigation.py`, `test_season_race_granularities.py`, `test_character_renderer.py`.
- 선수 ID 신호, 경기 시즌 전달, 이전 요청 배제, 월간/격주/기간 샘플, 로컬 계획, Full 확인/취소, 사진 실패 대체, 원형 이미지/캐시, GUI 스레드 밖 다운로드를 검증했습니다.
- 기존 라이트/다크/강조색·언어·이미지 내보내기 회귀 테스트도 통과했습니다.
- Python 컴파일 검사와 Git whitespace 검사를 통과했습니다. 이전 미리보기 패치의 검사·적용·원복 및 Git diff 적용도 별도 복사본에서 확인했습니다.
- Linux Qt offscreen 환경에서 검증했습니다. Windows 실화면 및 실제 MLB/FanGraphs 외부 통신은 이번 검증 범위에 포함하지 않았습니다.
- 테스트 환경의 CJK 폰트 부재로 Matplotlib 글리프 경고 19개가 발생했습니다. 데이터/기능 테스트 실패는 없습니다. 실제 환경에서는 한글·일본어 지원 폰트를 사용해 주세요.
